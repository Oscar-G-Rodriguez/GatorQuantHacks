## Statistical discovery and strategy registration

Exploratory statistics and prediction analysis may help form a candidate before it is registered; follow [the discovery rules](../AGENTS.md#statistical-discovery-before-a-hypothesis). Preserve every exploratory trial and final/organizer holdouts. The sequence below begins when a candidate advances to strategy implementation or backtesting.

1. Complete the folder's `Hypothesis.md`: mechanism, other side, persistence, prediction, falsification, data, timing, split, planned variants, costs, risk, and capacity assumptions. Resolve every consequential `TBD` before implementation.
2. Review the plan for feasible data availability and execution. Commit the completed plan before implementing its trading strategy or running a backtest. Use a descriptive hypothesis name in the commit message.
3. Record that commit hash in `Research Log.md` after it exists. The registration commit contains the plan; the later log records its identity. Do not add a made-up hash or amend the earlier commit just to place its hash inside itself.
4. Adapt the Webull code into that folder's own `backtest.py`, strategy, and analysis. Implement development/final-OOS separation, S01–S12 signal-reading methods, and the readable evidence contract. Review actual implementation and evidence coverage before final OOS. Tune on registered IS walk-forward periods only; record every variant and failure.
5. Freeze candidate selection, local code, settings, baselines, diagnostics, and cost/delay scenarios before final OOS. Evaluate the predeclared package once and report the result even if it is poor. A final supported incremental-signal verdict requires both IS validation and untouched OOS evidence.

From the repository root, an example registration sequence after completing the first hypothesis is:

```powershell
git add -- 'Hypotheses/Hypothesis 1/Hypothesis.md'
git commit -m 'Register hypothesis 1: <economic mechanism>'
git rev-parse HEAD
```

Review staged changes first so that the commit contains the intended registration. Replace the placeholder message with the actual mechanism. A commit of the starter or this blank template is only a preparation checkpoint.
