# Faster transport for the existing option study

Oscar identified the fixed request pace as an unnecessary delay and asked us to check subscription access and use bulk delivery where helpful. This transport amendment precedes its implementation. The completed study implementation was committed as `37c645c930f53012fe4db7b297f5a39131c017cc`; the H12–H17 statistical specification, selected contracts, development dates, request cap and HiPerGator execution remain those in [the shared plan](options-buffered-plan.md).

The existing downloader imposed 12.5 seconds between every request; that setting was not a verified restriction of Oscar's sponsor account. Massive's [request-limit documentation](https://massive.com/knowledge-base/article/what-is-the-request-limit-for-massives-restful-apis) says subscribed asset classes have unlimited requests, while unsubscribed classes have five per minute and reference endpoints have a separate bucket. Successful historical option-quote responses establish that those particular requests are accessible; they do not prove every entitlement or an unlimited rate.

Use a controlled half-second minimum interval for this acquisition, with separate option, stock and reference pacing buckets. The first uncached option/reference requests serve as a bounded access/rate observation and remain actual study requests, not extra datasets. Retain status, request timing, effective interval and any throttling receipt. On HTTP 429, slow that bucket to 12.5 seconds, wait at least 60 seconds or the supplied Retry-After delay, and allow at most two retries within the existing 2,000-request cap. Authorization errors remain explicit failures. Preserve the previous default pace for other callers. Completed immutable objects are reused on restart; record the interrupted attempt and the transport-plan commit in the resumed download receipt.

Massive also provides [daily option flat files](https://massive.com/docs/flat-files/options/day-aggregates): the documentation currently lists 644 MB for 2024 and 808 MB for 2025. Its [S3 setup](https://massive.com/docs/flat-files/quickstart) requires separate access and secret keys and Flat Files entitlement. Neither S3 key is configured in the repository's local environment. Do not invent or repurpose unrelated credentials, buy a subscription, or download the full options quote archive. For this already selected, partly cached sample, finish targeted acquisition first. If separate S3 access is later supplied, register a transport/source-comparison extension before using that additional source; keep raw bytes, file hashes and field equivalence explicit.

Validate cache reuse, independent pacing buckets, throttling delay/retry/cap behavior and unchanged conservative defaults with offline fixtures. Commit the transport code after those checks. Actual feature calculations, models and uncertainty estimates still run through the HiPerGator jobs.
